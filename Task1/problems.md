**Сопоставление процессов с требованиями безопасности и архитектурными практиками:**

* **Хранение данных:**
    * Текущее состояние: Использование Excel и сканов для хранения конфиденциальных данных.
    * Требования: Конфиденциальность, целостность, доступность, соответствие законодательству (ФЗ-152).
    * Архитектурные практики: Шифрование данных, контроль доступа, аудит, резервное копирование, использование защищенных баз данных.
    * Несоответствие: Хранение данных в незащищенном виде, отсутствие контроля доступа и аудита.
* **Передача данных:**
    * Текущее состояние: Передача данных между системами без шифрования.
    * Требования: Конфиденциальность, целостность.
    * Архитектурные практики: Использование защищенных каналов (HTTPS, VPN), шифрование данных при передаче.
    * Несоответствие: Отсутствие шифрования данных при передаче, риск перехвата данных.
* **Контроль доступа:**
    * Текущее состояние: Ограничения по доменной аутентификации.
    * Требования: Авторизация и аутентификация, разграничение прав доступа.
    * Архитектурные практики: RBAC (ролевое управление доступом), ABAC (атрибутивное управление доступом), LDAP, Active Directory.
    * Несоответствие: Отсутствие детального контроля доступа, риск несанкционированного доступа.
* **Аудит:**
    * Текущее состояние: Отсутствие аудита действий.
    * Требования: Отслеживание действий пользователей, обнаружение нарушений.
    * Архитектурные практики: SIEM-системы, логирование действий, анализ журналов.
    * Несоответствие: Отсутствие аудита, невозможность отслеживания нарушений.
* **Обработка PII:**
    * Текущее состояние: Ручная обработка персональных данных.
    * Требования: Соответствие ФЗ-152, защита PII.
    * Архитектурные практики: Минимизация данных, обезличивание, шифрование.
    * Несоответствие: Риски утечки данных, несоответствие законодательству.

**Список проблемных зон:**

* Незащищенное хранение конфиденциальных данных.
* Отсутствие контроля доступа и аудита.
* Незащищенная передача данных.
* Риски утечки данных из-за ручной обработки.
* Несоответствие законодательству РФ (ФЗ-152).
* Отсутствие политик безопасности.
* Отсутствие резервного копирования данных.
* Отсутствие планов восстановления после сбоев.
* Использование устаревшего программного обеспечения.
* Недостаточная осведомленность сотрудников о безопасности данных.
* Отсутствие инструментов DLP(Data Loss Prevention).

**Рекомендации:**

* Внедрить систему контроля доступа (RBAC/ABAC).
* Внедрить систему аудита действий.
* Шифровать данные при хранении и передаче.
* Обезличивать и маскировать PII.
* Внедрить политики безопасности данных.
* Перейти на защищённые базы данных.
* Проводить регулярное резервное копирование.
* Обучить сотрудников основам безопасности данных.
* Внедрить DLP системы.
